# 📦 مستندات جامع API — سیستم ثبت خسارت و ضایعات چندمرحله‌ای (Damage Registration)

> **مسیر ریشه API:** `/api/damage-registrations/`  
> **احراز هویت:** `Authorization: Bearer <access_token>` (Stateless Token)

---

## 🌟 ۱. نمای کلی سیستم (Overview)

سیستم ثبت خسارت و اقلام ضایعات در فروشگاه‌ها و شعب، جهت ثبت رسمی کالاها و گیاهان آسیب‌دیده و فرآیند تایید آن توسط سرپرست هر شعبه طراحی شده است:

1. **ثبت‌کنندگان مجاز:** انباردار (`WAREHOUSE`) و آمارگیر (`STATISTICIAN`) به همراه مدیران سیستم (`ADMIN`).
2. **انتخاب سرپرست شعبه:** ثبت‌کننده در هنگام ثبت اولیه، سرپرست شعبه مربوطه (`supervisor_id`) را انتخاب می‌کند.
3. **مرحله تایید سرپرست:** رکورد پس از ثبت، در وضعیت `PENDING_SUPERVISOR` قرار می‌گیرد و به کارتابل سرپرست ارسال می‌شود.
4. **تایید یا رد:** سرپرست شعبه (یا ادمین) می‌تواند پس از بررسی میدانی خسارت، آن را تایید (`APPROVED`) یا با ذکر دلیل رد (`REJECTED`) نماید.
5. **امکان لغو توسط ثبت‌کننده:** انباردار/آمارگیر تا قبل از بررسی سرپرست می‌تواند ثبت خود را لغو کند (`CANCELLED`).
6. **لاگ تاریخچه رویدادها:** تمام مراحل در جدول `DamageRegistrationLog` با ذکر عامل، تاریخ و زمان و توضیحات ثبت می‌شود.

---

## 🔄 ۲. نمودار چرخه حیات (Workflow State Machine)

```
[ثبت خسارت توسط انباردار یا آمارگیر]
           │
           ▼
[در انتظار تایید سرپرست (PENDING_SUPERVISOR)]
   ├── [لغو توسط ثبت‌کننده (CANCELLED)] (فقط قبل از بررسی سرپرست)
   ├── [رد توسط سرپرست (REJECTED)] (الزام نوشتن دلیل رد در فیلد note)
   └── [تایید توسط سرپرست (APPROVED)]
```

## 📑 ۳. جدول خلاصه Endpointها

| متد | آدرس Endpoint | شرح عملکرد | دسترسی و شروط |
|---|---|---|---|
| `GET` | `/api/damage-registrations/` | لیست ثبت‌های خسارت (خلاصه) | 🔐 سرپرستان، انبارداران و ادمین |
| `POST` | `/api/damage-registrations/` | ثبت خسارت و اقلام جدید | 🔐 انباردار، آمارگیر یا ادمین |
| `GET` | `/api/damage-registrations/{id}/` | مشاهده جزئیات کامل رکورد + اقلام + تاریخچه لاگ‌ها | 🔐 ثبت‌کننده، سرپرست منتسب، ادمین |
| `PUT/PATCH`| `/api/damage-registrations/{id}/` | ویرایش رکورد (فقط قبل از بررسی سرپرست) | 🔐 ثبت‌کننده یا ادمین |
| `POST` | `/api/damage-registrations/{id}/supervisor-review/` | تایید یا رد خسارت توسط سرپرست شعبه | 👑 سرپرست منتسب یا ادمین |
| `POST` | `/api/damage-registrations/{id}/cancel/` | لغو ثبت خسارت توسط ثبت‌کننده | 🔐 فقط ثبت‌کننده (در وضعیت انتظار) |
| `GET` | `/api/damage-registrations/my-inbox/` | کارتابل سرپرست (خسارت‌های ارجاع‌شده به من) | 👑 سرپرستان شعبه و ادمین |
| `DELETE` | `/api/damage-registrations/{id}/` | حذف گزارش خسارت | 👑 ادمین |

## 🔍 ۴. شرح دقیق Endpointها و نمونه Payloadها

### ۱. ثبت خسارت جدید (`POST /api/damage-registrations/`)

**دسترسی:** فقط کاربران دارای نقش `WAREHOUSE` (انباردار)، `STATISTICIAN` (آمارگیر) یا `ADMIN` (مدیریت).

#### بدنه درخواست (Request Body):
```json
POST /api/damage-registrations/
Content-Type: application/json

{
  "date": "2026-10-17",
  "branch": "شعبه بهشتی",
  "reason": "BREAKAGE",
  "culprit": "واحد حمل بار",
  "supervisor_id": 12,
  "description": "شکستگی در هنگام تخلیه بار در انبار شعبه بهشتی",
  "items": [
    {
      "item_name": "گلدان سرامیکی طرح کلاسیک",
      "quantity": 4,
      "unit_price": "180000.00"
    },
    {
      "item_name": "پایه چوبی گلدان",
      "quantity": 2,
      "unit_price": "250000.00"
    }
  ]
}
```

#### فیلدهای ورودی:
| فیلد | نوع | الزامی؟ | توضیح |
|---|---|:---:|---|
| `date` | تاریخ (`YYYY-MM-DD`) | ✴️ | تاریخ وقوع خسارت |
| `branch` | رشته | ✴️ | نام شعبه (`شعبه بهشتی`, `شعبه مدرس`, `شعبه سپیده`, `شعبه کاجستان`) |
| `reason` | رشته کد | ✴️ | علت: `IRRIGATION` (آبیاری), `PEST` (آفت), `BREAKAGE` (شکستگی), `LIGHT` (نور), `OTHER` (متفرقه), `UNKNOWN` (نامعلوم) |
| `supervisor_id` | شناسه کاربر | ✴️ | شناسه سرپرست شعبه منتخب جهت بررسی |
| `culprit` | رشته | ◻️ | نام یا مشخصات مقصر (در صورت وجود) |
| `description` | متن | ◻️ | توضیحات تکمیلی |
| `items` | آرایه اشیاء | ✴️ | اقلام خسارت‌دیده (حداقل یک مورد) |
| ↳ `item_name` | رشته | ✴️ | نام کالا |
| ↳ `quantity` | عدد صحیح | ✴️ | تعداد |
| ↳ `unit_price` | عدد اعشاری | ✴️ | قیمت واحد |

### ۲. بررسی و تایید یا رد توسط سرپرست (`POST /api/damage-registrations/{id}/supervisor-review/`)

**دسترسی:** سرپرست منتسب به گزارش (`supervisor`) یا مدیر سیستم (`ADMIN`).

#### الف) تایید خسارت:
```json
POST /api/damage-registrations/{id}/supervisor-review/
Content-Type: application/json

{
  "action": "approve",
  "note": "خسارت رویت شد و اقلام اسقاطی از چرخه خارج شدند."
}
```

#### ب) رد خسارت (نوشتن توضیحات `note` اجباری است):
```json
POST /api/damage-registrations/{id}/supervisor-review/
Content-Type: application/json

{
  "action": "reject",
  "note": "کالاها بررسی شد؛ شکستگی سطحی است و با تخفیف در فروشگاه عرضه می‌شود."
}
```

#### پاسخ موفق (HTTP 200 OK):
```json
{
  "message": "گزارش خسارت با موفقیت تایید شد."
}
```

### ۳. لغو ثبت توسط کاربر ثبت‌کننده (`POST /api/damage-registrations/{id}/cancel/`)

این متد به انباردار یا آمارگیر اجازه می‌دهد در صورتی که گزارش را اشتباه ثبت کرده باشند یا قبل از تایید سرپرست منصرف شوند، آن را لغو کنند. (نیازی به بدنه درخواست ندارد).

```http
POST /api/damage-registrations/{id}/cancel/
```

#### پاسخ موفق (HTTP 200 OK):
```json
{
  "message": "گزارش خسارت با موفقیت لغو شد."
}
```

#### خطای عدم امکان لغو (در صورت اقدام پس از بررسی سرپرست):
```json
{
  "error": "لغو فقط زمانی ممکن است که گزارش هنوز در انتظار تایید سرپرست باشد."
}
```

---

### ۴. کارتابل سرپرست شعبه (`GET /api/damage-registrations/my-inbox/`)

سرپرستان شعب می‌توانند گزارش‌های ارجاع‌شده به خود را به همراه اقلام و لاگ تاریخچه دریافت کنند.

#### پارامترهای اختیاری Query String:
* `status`: فیلتر وضعیت (`PENDING_SUPERVISOR` برای مواردی که نیاز به بررسی و تایید دارند)
* `branch`: فیلتر بر اساس نام شعبه
* `from_date` و `to_date`: بازه تاریخ خسارت
* `search`: جستجو در نام، نام خانوادگی، نام کاربری ثبت‌کننده یا مقصر

```http
GET /api/damage-registrations/my-inbox/?status=PENDING_SUPERVISOR
```

## 📊 ۵. جداول وضعیت‌ها و مراحل

### مقادیر وضعیت (`status`):
| مقدار در دیتابیس | عنوان فارسی | توضیحات |
|---|---|---|
| `PENDING_SUPERVISOR` | در انتظار تایید سرپرست | وضعیت اولیه پس از ثبت توسط انباردار یا آمارگیر |
| `APPROVED` | تایید شده توسط سرپرست | خسارت توسط سرپرست شعبه بررسی و تایید شد |
| `REJECTED` | رد شده توسط سرپرست | خسارت توسط سرپرست رد شد |
| `CANCELLED` | لغو شده توسط ثبت‌کننده | قبل از بررسی سرپرست توسط انباردار/آمارگیر لغو گردید |

### مقادیر مرحله لاگ (`stage` در `DamageRegistrationLog`):
| مقدار مرحله | عنوان فارسی |
|---|---|
| `SUBMIT` | ثبت اولیه |
| `SUPERIOR` | بررسی سرپرست |
| `CANCEL` | لغو توسط ثبت‌کننده |

## 🔒 ۶. خطاهای رایج (Error Handling)

| کد وضعیت | پیام خطا | علت |
|---|---|---|
| `400 Bad Request` | `ثبت خسارت فقط توسط انباردار یا آمارگیر (یا ادمین) امکان‌پذیر است.` | ثبت توسط کاربری فاقد نقش‌های مذکور |
| `400 Bad Request` | `کاربر انتخاب‌شده باید دارای نقش سرپرست یا ادمین باشد.` | ارسال `supervisor_id` متعلق به کاربری عادی یا صندوق‌دار |
| `400 Bad Request` | `برای رد گزارش خسارت، نوشتن توضیحات (note) الزامی است.` | رد بدون نوشتن متن در `note` |
| `403 Forbidden` | `شما سرپرست منتسب به این گزارش خسارت نیستید.` | تلاش سرپرست یک شعبه برای تایید گزارش شعبه/سرپرست دیگر |
| `400 Bad Request` | `گزارش خسارت پس از بررسی سرپرست قابل ویرایش نیست.` | تلاش برای ویرایش در وضعیت `APPROVED` یا `REJECTED` |
