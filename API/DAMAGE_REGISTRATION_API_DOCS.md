# 📦 مستندات جامع API — سیستم ثبت خسارت و ضایعات چندمرحله‌ای (Damage Registration)

> **مسیر ریشه API:** `/api/damage-registrations/`  
> **احراز هویت:** `Authorization: Bearer <access_token>` (Stateless Token)

---

## 🌟 ۱. نمای کلی سیستم (Overview)

سیستم ثبت خسارت و اقلام ضایعات در فروشگاه‌ها و شعب، جهت ثبت رسمی کالاها و گیاهان آسیب‌دیده با فرآیند تایید پنج‌مرحله‌ای طراحی شده است:

1. **ثبت‌کننده:** فقط سرپرستان شعب (`SUPERVISOR`) یا ادمین کل (`ADMIN`) می‌توانند ضایعات را ثبت نمایند. وضعیت اولیه رکورد پس از ثبت `PENDING_SALES_MANAGER` خواهد بود.
2. **انتخاب خودکار سرپرست:** فیلد `supervisor` به صورت پیش‌فرض همان سرپرست ثبت‌کننده در نظر گرفته می‌شود (در صورت ارسال `supervisor_id` در بدنه درخواست نیز اعمال می‌گردد).
3. **مرحله ۱ — تایید مدیر فروش:** رکورد پس از ثبت اولیه در وضعیت `PENDING_SALES_MANAGER` قرار می‌گیرد و توسط مدیر فروش (`SALES_MANAGER`) با ثبت توضیحات اختیاری بررسی و تایید/رد می‌شود.
4. **مرحله ۲ — تایید انباردار:** پس از تایید مدیر فروش، رکورد در وضعیت `PENDING_WAREHOUSE` قرار می‌گیرد و توسط انباردار (`WAREHOUSE`) یا آمارگیر (`STATISTICIAN`) با ثبت توضیحات اختیاری بررسی و تایید/رد می‌شود.
5. **مرحله ۳ — تایید مدیریت:** پس از تایید انباردار، رکورد در وضعیت `PENDING_MANAGEMENT` قرار می‌گیرد و توسط مدیریت (`ADMIN` یا `EXECUTIVE_MANAGER`) با ثبت توضیحات اختیاری بررسی و تایید/رد می‌شود.
6. **مرحله ۴ — تایید مدیر مالی:** پس از تایید مدیریت، رکورد در وضعیت `PENDING_FINANCIAL` قرار می‌گیرد و توسط مدیر مالی (`FINANCIAL_MANAGER`) با توضیحات اختیاری تایید نهایی (`APPROVED`) یا رد (`REJECTED`) می‌گردد.
7. **دسترسی‌های دیداری:**
   - **مدیر فروش، مدیر مالی، انباردار، آمارگیر و ادمین:** دسترسی کامل به **تمام ضایعات** ثبت‌شده در سیستم.
   - **سرپرست:** فقط ضایعات ثبت‌شده توسط خودش یا ارجاع شده به خودش را مشاهده می‌کند.
8. **امکان لغو توسط سرپرست ثبت‌کننده:** سرپرست ثبت‌کننده تا قبل از بررسی و تایید مدیر فروش یا انباردار (در وضعیت `PENDING_SALES_MANAGER` یا `PENDING_WAREHOUSE`) می‌تواند رکورد خود را لغو کند (`CANCELLED`).
9. **تاریخچه رویدادها (Audit Log):** تمام اقدامات و تاییدها در جدول `DamageRegistrationLog` با ذکر کاربر عامل، مرحله، تاریخ و زمان و توضیحات ثبت می‌شود.

## 🔄 ۲. نمودار چرخه حیات (Workflow State Machine)

```
[ثبت ضایعات توسط سرپرست یا ادمین]
              │
              ▼
  [در انتظار تایید مدیر فروش (PENDING_SALES_MANAGER)]
      ├── [لغو توسط سرپرست (CANCELLED)] (قبل از تایید مدیر فروش)
      ├── [رد توسط مدیر فروش (REJECTED)]
      └── [تایید توسط مدیر فروش]
              │
              ▼
  [در انتظار تایید انباردار (PENDING_WAREHOUSE)]
      ├── [رد توسط انباردار (REJECTED)]
      └── [تایید توسط انباردار یا آمارگیر]
              │
              ▼
  [در انتظار تایید مدیریت (PENDING_MANAGEMENT)]
      ├── [رد توسط مدیریت (REJECTED)]
      └── [تایید توسط مدیریت (توضیحات اختیاری)]
              │
              ▼
  [در انتظار تایید مدیر مالی (PENDING_FINANCIAL)]
      ├── [رد توسط مدیر مالی (REJECTED)]
      └── [تایید نهایی توسط مدیر مالی (APPROVED)]
```

| متد | آدرس Endpoint | شرح عملکرد | دسترسی و نقش‌های مجاز |
|---|---|---|---|
| `GET` | `/api/damage-registrations/` | لیست ثبت‌های ضایعات (خلاصه) | 🔐 سرپرستان (مال خود)، مدیر فروش، انبارداران، مدیر مالی و ادمین (همه) |
| `POST` | `/api/damage-registrations/` | ثبت ضایعات و اقلام جدید | 🔐 سرپرست شعبه یا ادمین سیستم |

| `PUT/PATCH`| `/api/damage-registrations/{id}/` | ویرایش رکورد (فقط قبل از بررسی مدیر فروش) | 🔐 سرپرست ثبت‌کننده یا ادمین |
| `POST` | `/api/damage-registrations/{id}/sales-manager-review/` | مرحله ۱: تایید یا رد ضایعات توسط مدیر فروش | 👑 مدیر فروش یا ادمین |
| `POST` | `/api/damage-registrations/{id}/warehouse-review/` | مرحله ۲: تایید یا رد ضایعات توسط انباردار | 👑 انباردار، آمارگیر یا ادمین |
| `POST` | `/api/damage-registrations/{id}/management-review/` | مرحله ۳: تایید یا رد ضایعات توسط مدیریت | 👑 مدیریت سیستم (ادمین یا مدیر اجرایی) |
| `POST` | `/api/damage-registrations/{id}/financial-review/` | مرحله ۴: تایید نهایی یا رد توسط مدیر مالی | 👑 مدیر مالی یا ادمین سیستم |
| `POST` | `/api/damage-registrations/{id}/cancel/` | لغو ثبت ضایعات توسط سرپرست ثبت‌کننده | 🔐 فقط سرپرست ثبت‌کننده (در وضعیت انتظار مدیر فروش) |
| `GET` | `/api/damage-registrations/my-inbox/` | کارتابل ضایعات (موارد منتظر اقدام کاربر فعال) | 👑 متناسب با نقش کاربر فعال |
| `DELETE` | `/api/damage-registrations/{id}/` | حذف گزارش ضایعات | 👑 ادمین |

## 🔍 ۴. شرح دقیق Endpointها و نمونه Payloadها

### ۱. ثبت ضایعات جدید (`POST /api/damage-registrations/`)

**دسترسی:** فقط کاربران دارای نقش `SUPERVISOR` (سرپرست شعبه) یا `ADMIN` (مدیریت).

#### بدنه درخواست (Request Body):
```json
POST /api/damage-registrations/
Content-Type: application/json

{
  "date": "2026-10-22",
  "branch": "شعبه بهشتی",
  "reason": "BREAKAGE",
  "culprit": "واحد حمل بار",
  "description": "شکستگی در هنگام تخلیه بار در انبار شعبه بهشتی",
  "items": [
    {
      "item_name": "گلدان سرامیکی طرح کلاسیک",
      "quantity": 4,
      "unit_price": "180000.00"
    },
    {
      "item_name": "پایه چوبی گلدان",
      "quantity": 2,
      "unit_price": "250000.00"
    }
  ]
}
```

> **نکته:** فیلد `supervisor_id` اختیاری است. اگر ارسال نشود، به صورت خودکار کاربر لاگین‌شده سرپرست به عنوان سرپرست رکورد ثبت می‌گردد. وضعیت اولیه `PENDING_SALES_MANAGER` خواهد بود.

---

### ۲. مرحله ۱: تایید یا رد توسط مدیر فروش (`POST /api/damage-registrations/{id}/sales-manager-review/`)

**دسترسی:** کاربران دارای نقش `SALES_MANAGER` (مدیر فروش) یا `ADMIN`.

#### بدنه درخواست:
```json
POST /api/damage-registrations/{id}/sales-manager-review/
Content-Type: application/json

{
  "action": "approve",
  "note": "تایید اولیه شد و به انباردار ارجاع گردید."
}
```
* `action`: مقدار `approve` (تایید و ارجاع به انباردار) یا `reject` (رد گزارش ضایعات).
* `note`: توضیحات اختیاری.

#### پاسخ موفق:
```json
{
  "message": "گزارش ضایعات با موفقیت تایید و به انباردار ارجاع شد."
}
```

---

### ۳. مرحله ۲: تایید یا رد توسط انباردار (`POST /api/damage-registrations/{id}/warehouse-review/`)

**دسترسی:** کاربران دارای نقش `WAREHOUSE` (انباردار)، `STATISTICIAN` (آمارگیر) یا `ADMIN`.

#### بدنه درخواست:
```json
POST /api/damage-registrations/{id}/warehouse-review/
Content-Type: application/json

{
  "action": "approve",
  "note": "اقلام از نزدیک مشاهده و تایید گردید."
}
```
* `action`: مقدار `approve` (تایید و ارجاع به مدیریت) یا `reject` (رد گزارش ضایعات).
* `note`: اختیاری.

#### پاسخ موفق:
```json
{
  "message": "گزارش ضایعات با موفقیت تایید و به مدیریت ارجاع شد."
}
```

---

### ۴. مرحله ۳: تایید یا رد توسط مدیریت (`POST /api/damage-registrations/{id}/management-review/`)

**دسترسی:** کاربران دارای نقش `ADMIN` یا `EXECUTIVE_MANAGER`.

#### بدنه درخواست:
```json

Content-Type: application/json

{
  "action": "approve",
  "note": "مورد تایید مدیریت است."
}
```

#### پاسخ موفق:
```json
{
  "message": "گزارش ضایعات با موفقیت تایید و به مدیر مالی ارجاع شد."
}
```

**دسترسی:** کاربران دارای نقش `FINANCIAL_MANAGER` (مدیر مالی) یا `ADMIN`.

#### بدنه درخواست:

POST /api/damage-registrations/{id}/financial-review/

---

### ۶. لغو توسط سرپرست ثبت‌کننده (`POST /api/damage-registrations/{id}/cancel/`)

**دسترسی:** فقط کاربر ثبت‌کننده سرپرست (یا ادمین) تا قبل از بررسی و تایید مدیر فروش (`PENDING_SALES_MANAGER`).

```json
POST /api/damage-registrations/{id}/cancel/
```

#### پاسخ موفق:
```json
{
  "message": "گزارش ضایعات با موفقیت لغو شد."
}
```

---

### ۷. کارتابل هوشمند کاربر (`GET /api/damage-registrations/my-inbox/`)

این Endpoint به طور هوشمند بر اساس نقش کاربر درخواست‌دهنده، موارد نیازمند اقدام را برمی‌گرداند:
* برای **مدیر فروش:** موارد در انتظار تایید مدیر فروش (`PENDING_SALES_MANAGER`).
* برای **انباردار و آمارگیر:** موارد در انتظار تایید انباردار (`PENDING_WAREHOUSE`).
* برای **مدیریت:** موارد در انتظار تایید مدیریت (`PENDING_MANAGEMENT`).
* برای **مدیر مالی:** موارد در انتظار تایید مدیر مالی (`PENDING_FINANCIAL`).
* برای **سرپرست:** کلیه ضایعات ثبت‌شده توسط او جهت پیگیری وضعیت گردش کار.

## 🔒 ۵. ماتریس وضعیت‌ها و دسترسی‌ها

| کد وضعیت | عنوان فارسی | اقدام بعدی | بررسی‌کننده مجاز |
|---|---|---|---|
| `PENDING_SALES_MANAGER` | در انتظار تایید مدیر فروش | بررسی اولیه فروش | مدیر فروش |
| `PENDING_WAREHOUSE` | در انتظار تایید انباردار | بررسی میدانی اقلام | انباردار / آمارگیر |
| `PENDING_MANAGEMENT` | در انتظار تایید مدیریت | بررسی سیستمی و تایید اولیه | مدیریت (Admin / مدیر اجرایی) |
| `PENDING_FINANCIAL` | در انتظار تایید مدیر مالی | بررسی و تایید نهایی مالی | مدیر مالی |
| `APPROVED` | تایید نهایی شده | پرونده بسته و تایید شد | — |
| `REJECTED` | رد شده | گزارش رد شد | — |
| `CANCELLED` | لغو شده | لغو توسط ثبت‌کننده | — |
